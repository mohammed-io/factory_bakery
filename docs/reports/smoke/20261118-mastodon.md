# Smoke test — Mastodon (2026-11-18)

FactoryBakery real-world smoke run against Mastodon main through the cached deterministic
pipeline (`real-world-rails-smoke` skill, `scripts/deterministic_smoke.rb`): schema + models
extracted into a temporary SQLite harness, models baked (unsaved) and validated one by one.
No app bootstrap (no Postgres/Redis/Elasticsearch).

This was the **first project to run the new pipeline end-to-end** — the script was
syntax-checked but never executed before this run. 12 script bugs were found and fixed along
the way (list below); all fixes are in the script and the tuned state is cached.

## Failure signatures (grouped)

### Gem findings (actionable in factory_bakery)

1. **Required `belongs_to` presence dominates (29/34 invalids)** — `<parent> must exist` on
   nearly every model with required associations (`AccountDeletionRequest`,
   `AccountModerationNote`, the whole `Fasp::*` family, `CustomFilter*`, `BulkImportRow`…).
   Unsaved-bake semantics; Mastodon is far more association-dense than Discourse's first-50
   (which scored 90 %). Cross-reference: the `belongs_to` auto-build feature landed mid-run
   (`5d4219e`) and did **not** change these outcomes on an empty DB — needs a look at why the
   auto-build path is not engaging here (opt-in `:required_only` mode?).
2. **Filler trusts blank DB defaults before presence validators (4 models)** —
   `Announcement` (`text`, `default: ""`), `DomainAllow`/`DomainBlock`/`EmailDomainBlock`
   (`domain`). `filler_selector.rb:69` selects the noop filler for any defaulted column before
   validator requirements are consulted; a blank default + `presence: true` ⇒ guaranteed
   invalid. Candidate fix: presence-validated columns should outrank the has-default noop.
3. **PG-array column fed a String into an array API (1 model)** — `CustomFilter`:
   `NoMethodError: undefined method 'map' for String` at `custom_filter.rb:47` (validator maps
   the `context` array column; filler produced a String). Same json/array column-type gap
   Discourse showed (`AppearanceChange`); Mastodon adds a second datapoint (`array: true`
   columns, not just jsonb).
4. **`FeaturedTag` bakes for >20 s (timeout)** — CPU spin under the new
   `UniquenessEnforcer`/filler path on an empty DB. Bounded by the runner's per-model timeout;
   worth profiling which fill loop spins.

### App-specific limitations (not gem defects)

5. **`Mastodon::Version.prerelease`** (`Account`, `CustomEmoji`) — version module reads repo
   metadata absent from the harness (`nil[...]`).
6. **Validators requiring persisted/nested state** — `Collection#user_does_not_exceed_limit`
   (`user` nil), `CollectionItem#local?` (delegates to nil `collection`), `Appeal#
   validate_time_frame` (`appeal_eligible?` on nil), `Backup`/`Conversation`
   `InverseOfAssociationNotFoundError` (declared inverse missing on the other side).
7. **Derived-field validators** — `CanonicalEmailBlock`: `canonical_email_hash` presence with
   the plain hash column never set by a heuristic filler.
8. **Missing i18n/repo assets** — `AccountPin` (`Translation missing: en.accounts.pin_errors
   .following`), `AnnouncementReaction` (emoji_map.json), `PrivacyPolicy`/`TermsOfService`
   (config/templates markdown).

## Schema adaptation notes (schema.rb → SQLite, all mechanical, in-script)

| adaptation | why |
|---|---|
| `t.jsonb→t.json`, `t.uuid/inet/citext/hstore/bytea→string/text/binary` | PG types |
| drop `array:` option + PG array defaults (`default: []`) | SQLite3 rejects the option; Ruby-array defaults unquotable |
| drop `create_table` lambda defaults (`timestamp_id(...)` snowflake PKs, 7 tables) | adapter emits `DEFAULT (timestamp_id('accounts'::text))` — invalid SQLite |
| strip expression / `NULLS LAST`-ordered indexes (top-level `add_index` **and** inline `t.index`) | SQLite rejects casts and NULLS-ordering in index DDL |
| drop `enable_extension`, scenic `create_view` heredocs (`instances` materialized view) | PG-only; view-targeted `add_index` lines dropped by table tracking |

## Script bugs found & fixed during bring-up (12)

1. Missing `require "shellwords"` (`String#shellescape` NoMethodError at startup).
2. `Open3.capture2e(..., chdir: nil)` → `spawn` TypeError; option now passed only when set.
3. Cone-mode `git sparse-checkout set` rejected the `Gemfile` file pattern → `--no-cone` with
   root-anchored patterns.
4. Clone-failure guard `sh(...) or exit 2` never fired (`sh` returns a truthy Array).
5. Dead index-stripper regexes (a literal `Civic` token matched nothing) → line-based state
   machine (see adaptation table).
6. `array: true → array: false` still raises on SQLite3 — the option is now dropped outright.
7. PG array defaults (`default: []`) now stripped (were left in place).
8. Lambda PK defaults (`default: -> { ... }`) now dropped (the old `→ nil` rewrite didn't match
   the dumper's form and the adapter passes the lambda string through as raw SQL).
9. **Case-insensitive-APFS trap**: `Dir[]` returns canonical-case paths (`/Users/mohammed/
   Projects/…`) while `--gem-root` came in lowercase — the prefix-strip in the model copy
   silently failed and nested the whole clone under `harness/app/models/Users/mohammed/…`;
   the runner then saw 1 model. Fixed with `File.realpath` canonicalization.
10. `ActiveRecord::Base.descendants` was empty under `rails runner` (no eager load) →
    tolerant per-file require pass with realpath-aware dedup (Zeitwerk autoloads can
    double-execute files and leave two class objects with one name — descendants now deduped
    by name), plus `upstream_lib/` extraction + `$LOAD_PATH` mirroring for upstream `lib/`
    (see below), baked into the runner.
11. `lib/` support trees added to the sparse checkout and scaffolded to `upstream_lib/` —
    deliberately **not** `lib/`, because the Rails 8 template's `config.autoload_lib` makes
    Zeitwerk scan it and choke on `json-canonicalization`. `upstream_lib` is invisible to
    Zeitwerk and required by path, restoring upstream boot-order semantics (`lib/mastodon`,
    `lib/chewy` patches, `lib/vite`, devise strategies).
12. Bake loop now rescues `ScriptError` (LoadError/SyntaxError are not `StandardError`) and
    wraps each model in `Timeout.timeout(20)` — a spinny filler records a `timeout` line
    instead of hanging the pipeline (the earlier unbounded run burned 8 min of CPU on
    `FeaturedTag` before being killed).

## Verdict

10.0 % pass rate on Mastodon's first 50 distinct models — an honest first contact with an
association-dense app: 29 of the 34 invalids are the single `belongs_to`-presence signature,
and the 4 remaining gem-actionable invalids collapse into two findings (blank-default vs
presence; array-column filler). Zero schema-translation blockers: Mastodon's `db/schema.rb`
loads mechanically on SQLite after in-script adaptations. The pipeline itself emerged
battle-tested: 12 script bugs fixed, cache entry valid, and reruns are HIT-fast.
